# Research Agent System · 系统设计 v5

**版本**: v5

**依据**: 《AutoResearch PRD 与四人分工(1).docx》（2026-11-14）

**产品名**: AutoResearch · 量价信号验证工作台

**一句话**: 给 AutoResearch 一份日频量价数据和运行预算，它在 ARC 的阶段框架下自主完成“数据画像 → 固定基线 → 提出假设 → 执行实验 → 验证 → 修正 → 锁定候选 → 独立测试 → 复现报告”，记录哪些假设被证据推翻，并让每一步的 token 消耗、时间、结论和回退都可查。

---

## 0. 变更说明（v4 → v5）

| 维度 | v4 | v5（本版） |
|---|---|---|
| 场景 | 通用轻量表格分类 | AutoResearch：日频量价信号验证工作台 |
| 研究问题 | 表格二分类 | 未来 5 日收益是否高于同日样本中位数 |
| 基线 | 自定默认 pipeline | PRD 固定：`LogisticRegression[r5, r20]` |
| 数据 | 任意合规 CSV | CSV 至少含 `date/symbol/close/volume`，`(date,symbol)` 唯一 |
| 指标 | holdout F1/AUC | 按交易日计算 ROC AUC，全有效日均值 |
| 切分 | 60/20/20 分层随机 | 按日期分组：60% 训练 / 两个连续验证窗 / 20% 独立测试，5 交易日标签间隔 |
| 默认预算 | 抽象配额 | 4 个候选实验、3 次云调用、6,000 云 token、180 秒墙钟 |
| 四人分工 | 泛化角色 | 明确 A/B/C/D：编排、数据模型、评测复现、界面集成，附 10 小时排期 |
| 验收 | 自定义清单 | PRD 四条：闭环、预算、验证、复现 |

保留 v4 不变的四件事：

1. 独立裁判层只由 oracle 出分，Agent 不能自评；
2. 假设先预注册、结果后判定，可算命中率；
3. 策略/计划经由闸门与版本链，可回退、可回放；
4. 系统自身按成本、完成度、完成时间、自迭代能力评估。

## 1. 产品定义与研究任务

### 1.1 面向谁

AutoResearch 面向量化研究员。研究员只需提供日频量价 CSV 和运行预算，系统自主检验短期量价特征是否具有样本外预测价值，记录哪些假设被证据推翻，并交付可复现的实验报告。

### 1.2 主研究任务

每天收盘后，使用当时已知的价格与成交量信息，预测每只股票未来 5 个交易日的收益是否高于同日样本股票收益的中位数。

- 标签：`fwd5_ret > median(fwd5_ret)`（严格大于）；
- 固定基线：5 日与 20 日收益率特征的逻辑回归；
- Agent 检验对象：波动率、成交量变化、非线性模型等能否带来稳定改善；
- 研究结论允许三种：**有提升**、**未验证到提升**、**证据不足**。

### 1.3 P0 / P1 范围

| 范围 | 内容 |
|---|---|
| P0 | 单任务、单页 Streamlit、日频二分类、CPU 实验、至少一次基于证据的修正、云调用预算门控、独立测试、报告导出 |
| P1 | 跨运行复用失败记录、第二份数据或任务、额外分段图 |
| 明确不做 | 实盘接入、组合管理、交易回测、NPU 接入 |

技术栈沿用：Python、Pandas、scikit-learn、Streamlit。

## 4. 研究闭环与状态机

### 4.1 主循环

```
启动
  → 数据画像与固定基线
  → 提出假设（预注册预测与证据编号）
  → 执行实验（train/val，只允许一个特征组或一个模型设置变化）
  → 验证（两窗日均 AUC + 0.01 淘汰规则 + 泄漏检查）
  → 根据证据修正（引用证据编号，重跑同一切分）
  → 锁定候选
  → 独立测试（holdout 只评一次）
  → 生成报告与复现包
```

### 4.2 节点状态机

```
UNSEEN
  → PLANNING        (规划 Agent：生成假设与实验配置)
  → PLANNED         (假设预注册、验证规格生成)
  → EXPERIMENTING   (实验 Agent：本地执行)
  → VERIFIED        (验证 Agent 出判)
  → REVISED         (证据导致计划/配置变化)
  → LOCKED          (锁定候选或基线)
  → TESTED          (独立测试完成)
  → PASSED / CONVERGED / FAILED

分支：
VERIFIED → evidence 不足 / 两窗矛盾 → REVISED 或升级云诊断
预算或时间不足 → CONVERGED（保存最佳已验证结果）
实验数/调用数/超时触顶 → FAILED 或“部分完成”
```

内部沿用 ARC 的节点状态命名：`UNSEEN / DESIGNING / DESIGNED / IMPLEMENTING / PASSED / CONVERGED / FAILED`，语义按上表。

## 5. 数据、标签与切分协议

### 5.1 数据输入

CSV 至少包含：

```
date, symbol, close, volume
```

- `(date, symbol)` 组合唯一；
- 开赛后优先使用组委会许可数据，实际列名由数据适配器映射；
- 历史快照统一价格口径，记录当时可得的标的范围与来源；
- 固定种子的合成面板仅用于离线联调，现场明确标注数据类型；
- 数据随包携带并计算 `sha256`。

### 5.2 标签定义

以 t 日收盘为特征截止点：

- 用共同交易日历计算 t 至 t+5 的收益；
- 比较同一 t 日可计算标签的标的收益中位数；
- 严格高于中位数记 1，其余记 0；
- 缺少 t+5 收盘价的样本排除并计数；
- 禁止用下一条可用行情替代缺失的 t+5。

### 5.3 训练 / 验证 / 独立测试

按交易日期整体分组后切分：

| 分段 | 占比 | 用途 |
|---|---|---|
| 训练 | 前 60% | 拟合插补、缩放与模型 |
| 验证窗 1 | 其后 20% 的一半 | 候选评估 |
| 验证窗 2 | 其后 20% 的一半 | 候选评估 |
| 独立测试 | 最后 20% | 锁定后只评一次 |

规则：

- 对训练及各验证窗口尾部清除标签跨入后续窗口的样本，按 5 个交易日预留间隔；
- 任一分段没有足够有效交易日时提示“证据不足”；
- 滚动特征按标的计算，只读历史与当日数据；
- 所有插补、缩放和模型只在训练数据上拟合；
- Agent 可读训练与验证摘要；
- 锁定候选前，测试结果对 Agent 和界面封闭；
- 锁定后基线与候选各评一次，测试分数只用于报告。

### 5.4 主指标

逐交易日计算 ROC AUC，再对两类都出现的有效交易日等权平均：

```
main_metric = mean( auc(day) for day in valid_days )
```

- 某日只有一个类别 → 当日不计入，并计数；
- 报告两验证窗、独立测试、有效天数与排除样本数；
- 0.01 为预设容差。

## 6. 假设轴与实验空间

### 6.1 实验空间

实验模型限制为逻辑回归或浅层树模型（如 `max_depth<=5` 的决策树/浅随机森林）；候选特征组：

| 特征组 | 内容 |
|---|---|
| 基础收益 | `r5`、`r20`（基线） |
| 历史波动率 | 滚动标准差、波动比例 |
| 成交量变化 | 相对成交量、量比、量能变化率 |

单轮实验只改变一个特征组或一个模型设置，便于解释。

### 6.2 可学习轴（示例）

| 轴 | 问题 | 假设 |
|---|---|---|
| `features` | 加哪组特征 | `base` / `+volatility` / `+volume` / `+volatility_volume` |
| `model` | 用什么模型族 | `logistic` / `tree_shallow` |
| `missing` | 缺失怎么处理 | `drop` / `median` / `constant` |
| `scaling` | 数值特征怎么缩放 | `none` / `standard` / `robust` |

### 6.3 预注册假设示例

| 编号 | 假设 | 预测 | 判据（事前写入） |
|---|---|---|---|
| H1 | 加入历史波动率组可提升日均 AUC | high | 合并两窗均值高于基线且任一窗不掉超过 0.01 |
| H2 | 加入成交量变化组可提升日均 AUC | low（预判可能无益） | 同上；无提升或被淘汰则入账 |
| H3 | 浅层树在基础+波动率上优于逻辑回归 | high | 合并均值更高且单窗不劣于 0.01 |
| H4 | 缩放缺失处理组合可稳定两窗 | high | 两窗同时不低于当前最优 |

每条假设生成时记录：预期效果、证据编号、实验配置、预测理由。

### 6.4 修正示例

PRD 给定修正示例：相对成交量加入后，后一验证窗 AUC 下滑且其缺失率上升。

Agent 必须：

1. 引用这两项证据编号；
2. 提出可执行修正：移除该特征组，或只改变缺失处理；
3. 重跑同一切分；
4. 把“上一轮证据如何改变本轮配置”写入日志。

## 7. Agent 角色与路由

### 7.1 三个职责

| 职责 | 输入 | 输出 | 执行方式 |
|---|---|---|---|
| 规划 Agent | 任务、数据摘要、工具清单、历史证据 | 结构化假设、预期效果、证据编号、实验配置 | 确定性模板起步；候选排序困难且预算允许才调用云模型 |
| 实验 Agent | 实验配置与切分 | 每个验证窗分数、缺失率、耗时、实验编号 | 本地白名单工具；模型只能选择允许的特征组和参数 |
| 验证 Agent | 实验结果与规则 | 接受 / 修正 / 结束，引用证据编号 | 规则处理常见问题；窗口结论冲突或诊断失败时可调用同一云模型 |

> 明确：三个职责共用一个 Python 编排器和同一个云模型。角色是提示词、工具权限与输出契约的区别，不是模型数量的区别。

### 7.2 本地规则优先

以下情况由本地规则直接处理，不调用云：

- 缺字段 / schema 校验失败；
- 实验重复（特征、配置、模型、参数、切分指纹相同）；
- 单一特征组缺失率异常（如 > 30%）；
- 结果可直接按 0.01 规则判决。

### 7.3 云调用触发

以下情况发送紧凑摘要给云模型：

- 两个验证窗口方向相反，且简单规则无法归因；
- 连续两轮无候选通过 / 两次无进展；
- 关键判断影响后续 ≥ 3 步；
- 收尾成文。

云模型回包必须是可执行修正，并引用证据编号；回包无效则记录失败并回到规则路径。

每次云调用记录：

```json
{
  "event": "escalation",
  "trigger": "window_conflict",
  "summary_hash": "sha256:...",
  "tokens": {"input": 1200, "output": 640},
  "remaining_budget": 3200,
  "decision": "remove volume feature group",
  "evidence_ids": ["E23", "E24"],
  "valid": true
}
```

## 8. 预算、成本与降级

### 8.1 默认预算

| 资源 | 默认上限 |
|---|---|
| 候选实验 | 4 个 |
| 云调用 | 3 次 |
| 云 token | 6,000 |
| 墙钟时间 | 180 秒 |

- 基线与最终测试单独计时，计入总时长；
- 候选实验启动前预留最终测试与报告时间；
- 官方给定额度或现场计时变化时统一覆盖配置。

### 8.2 调用前估算

- 按可用分词器核算输入 token，并预留最大输出；
- 请求超时受剩余时间约束；
- 若估算后无法建立可信上界，跳过云调用并在日志写明原因；
- 结束后按供应商 `usage` 结算；缺失则标记 `estimated` 或 `unknown`，并保留预留额；
- 计价未公布时只显示 token，不填虚构金额。

### 8.3 实验执行纪律

- 实验以可超时终止的工作进程运行；
- 达到实验上限、无合法新候选或超时时：保存日志和最佳已验证结果；
- 剩余时间足够才执行锁定测试，否则结论标为“部分完成”；
- token 账本使用共享文件原子累加，跨进程一致。

### 8.4 预算不足演示

验收要求：把预算设得不足时，请求被拦截，页面可见剩余预算与处理结果。设计上：

- 每次云调用前检查 `estimated + reserve <= remaining`；
- 不满足则写 `budget_blocked` 事件并降级到规则路径；
- 剩余实验与云调用配额同步显示。

## 9. 验证与裁判（oracle）

裁判是唯一出分口，Agent 没有写 verdict 的权限：

```
oracle.judge(run_id, experiment_id, locked_config)
```

裁判检查：

1. 切分指纹与数据哈希一致；
2. 标签成熟：尾部样本已按 5 日间隔清除；
3. 特征时间顺序：滚动特征只用历史与当日；
4. 拟合边界：插补/缩放/模型只在训练段拟合；
5. 独立测试只在锁定后调用一次；
6. 重复指纹：同配置不重跑；
7. 预算记录：token / 时间 / 调用次数合法。

输出：

```json
{
  "verdict": "supported",
  "metric": {"val1_auc": 0.621, "val2_auc": 0.634, "merged_auc": 0.628},
  "test": {"auc": 0.647, "valid_days": 486, "excluded": 120},
  "checks": ["split_hash_ok", "label_maturity_ok", "no_leakage"],
  "tokens": 0,
  "seconds": 42.0
}
```

verdict 可选：`supported` / `refuted` / `inconclusive` / `blocked` / `partial_completed`。

| 时间 | 完成条件 |
|---|---|
| 0-1 小时 | 确认赛方数据、调用限制与四人认领；冻结协议、样例 CSV 和事件 JSON |

### 12.4 前端：要不要加、加多少

**结论：要加，但按 PRD 只加 P0 要求的最薄单页 Streamlit。**

理由：

1. PRD 的 P0 白纸黑字包含单页 Streamlit、运行表单、研究时间线、结果对照和报告下载；
2. 验收项“预算”要求页面上可见剩余预算与处理结果，“闭环”和“验证”也依赖可视化证据；
3. 三分钟现场演示需要一台可直接操作的评审界面，而不是让评委看终端。

前端角色限定：

- 只读后端已经发生的事件、指标和判决，不做任何业务决策；
- 不直接调用 LLM、不触发实验、不写 holdout、不生成结论；
- 所有 token、时间、预算读数都来自 `RunEvent` 和 `token_ledger.json`，前端只负责展示；
- 报告下载由 `report.py` 在复现包生成后提供，前端只暴露入口。

P0 页面上必须有的内容：

| 区块 | 内容 |
|---|---|
| 创建任务 | 选择内置演示数据或导入合规 CSV、显示日期范围与字段、设置预算后启动 |
| 跟踪研究 | 逐轮展示假设、引用的数据证据、验证窗口分数、失败原因与下一步；右侧显示 token、调用次数、耗时和停止原因 |
| 审查结论 | 对比固定基线与已锁定候选的独立测试表现，查看保留基线或结束研究的理由，下载复现包 |

P0 页面不要做：

- 登录注册、权限系统、多项目后台；
- 实时流式长连接、动画、复杂图表库；
- 让用户手改实验配置后直接进 holdout；
- 任何“前端也能调模型”的能力。

降级方案（时间不足时）：

- 保留单页 + 表格，砍掉时间线图形化，只保留结构化时间线；
- 若 Streamlit 依赖或环境损坏，保留 `python -m autoresearch.cli run` 的 CLI 全流程演示，并在评审时明说“界面是薄壳，核心在编排与裁判”；
- 现场演示优先走 UI；断网或 UI 异常时走“回放 + CLI 本地规则路径”。

## 13. 系统自评估方案

### 13.1 三臂对照

| 臂 | 做法 | 云调用 |
|---|---|---|
| A 固定顺序本地搜索 | 依次跑预置候选列表，纯规则选最好 | 0 |
| B 贪婪全模型 | 每次要选实验都尝试云调用，同预算上限 | 同 6,000 token / 3 次上限 |
| C 证据触发（主臂） | 本地规则优先，只有结构性触发才云调用 | 同预算上限 |

按 PRD：两种云模式共用一个模型和相同预算上限。B 提前耗尽本身就是对照结论，不另设高额预算。

### 13.2 指标表

| 指标 | 定义 |
|---|---|
| 闭环完成 | 自动完成基线、候选、至少一次证据修正、锁定与测试 |
| 独立测试 AUC | 锁定后唯一一次 holdout 评分 |
| 候选次数 | 实际执行的候选实验数 |
| 云调用次数 | prompt/completion 调用记录 |
| token 成本 | 供应商 usage 合计；缺失标 estimated / unknown |
| 费用 | 有单价才换算，否则只报 token |
| 墙钟时间 | 从启动至报告生成的秒数 |
| 加速比 | 达到同等独立测试质量时，B 耗时 ÷ C 耗时；B 未达标则报 A/B/C 能力边界 |
| 质量/成本 | 独立测试提升 ÷ 每 10k token |
| 负结果率 | refuted / inconclusive 实验 ÷ 实验总数 |
| 升级命中率 | 云回包被后续实验验证的比例 |
| 预算拦截率 | `budget_blocked` 次数 ÷ 请求次数 |

### 13.3 自迭代硬证据

**证据 A：同题更省**

同一数据、同一 seed、同一依赖版本，第二次运行达到同样的独立测试口径，比第一次少花 ≥ 20% token（或墙钟更短）。策略/失败记录被复用。

**证据 B：换题迁移**

第二份数据达到“基线 + 目标提升”所需 token，比第一份数据首次运行少 X%。

> 注：证据 B 依赖 P1 的第二份数据；若 P0 冻结后时间不足，以“同题二次运行 + 一份离线备用数据”完成演示。

### 13.4 评估矩阵

| 数据 | 臂 | 重复 |
|---|---|---|
| 演示面板（固定 seed） | A/B/C | 条件允许时 3 次，报中位数与完成次数 |
| 第二数据集（P1） | C | 至少 1 次 |

## 16. 风险与对策

| 风险 | 对策 |
|---|---|
| 基线实测低于 0.5（短期反转） | 不篡改 PRD 基线；如实报告。候选仍需证明显著超过该基线 |
| 场景没有信号 | 前置门：先跑基线 + 3 候选，两窗显著且 0.01 规则成立才继续 |
| 云调用一次都不触发 | 结构化触发 + 彩排预验证；预算不足分支也必须演示 |
| 看起来像 AutoML | 展示假设证伪、证据引用、修正记录、负结果与升级命中率 |
| 单 LLM 被包装成多模型 | 全篇明确“三个职责共享一个云模型” |
| token 口径不可信 | usage 入账；缺失标 estimated/unknown；禁止填 0 或虚构金额 |
| 现场超时 | 180 秒墙钟、进程超时终止、时间预留、低预算演示 |
| holdout 被碰 | oracle 只读文件 + 阶段纪律禁止写测试段 |
| 复现不一致 | 数据哈希、切分指纹、种子、依赖 lock、事件流、复现命令 |
| 四人接口冲突 | 0-1 小时冻结契约；A/B 与 C/D 交叉验收 |

## 18. 尚需完善与现场决策

按“写代码前 / 实现中 / 收尾”三档列出，前五项没有完成之前不要写 agent 主循环。

### 18.1 写代码前（必须先落地）

1. **前置门脚本**：实现 `pre_gate.py` + 演示面板，跑“固定基线 + 3 个候选”，输出两窗 AUC、CI 和结论；不通过就换数据/换池/换标签，不写主循环。
2. **演示数据**：生成或取得合规 CSV（`date/symbol/close/volume`），固定 seed、`sha256`、切分；如果 PRD 基线的实测结果低于 0.5 或候选无显著提升，回到 v2 的教训：换面板或换标签口径，并在报告中如实写出。
3. **噪声口径**：PRD 保留 0.01 淘汰规则；另加配对 bootstrap 95% CI 作为“是否显著提升”的次级检查，避免 0.01 决定被窗口噪声带偏。CI 跨 0 的结论标 `inconclusive`。
4. **三臂对照口径冻结**：B 未达标时加速比怎么写、`partial_completed` 怎么计、完成率的分子分母是什么，先写进 `evaluate.py` 的注释与 README，再编码。
5. **契约冻结**：`TaskSpec / ExperimentSpec / TrialResult / RunEvent` 用 pydantic/jsonschema 校验，附样例 JSON 和一份模拟事件文件供 D 联调。

### 18.2 实现中（进入 P0 编码后）

6. **oracle 对抗测试**：构造一个“无泄漏但分数变好”的伪造实验，oracle 必须拒绝；这条是评审最可能当场按的按钮。
7. **自动化测试**：标签成熟、切分边界、重复指纹、预算拦截、回包校验各一条测试；新增 `core/research/tests/` 并接入现有 `core/evolution/tests/run_all.py`。
8. **token 账本细节**：定义估算函数（输入长度 → token）、`max_tokens` 预留、`estimated / unknown / actual` 三种标记；实际用量超过预留时的处理方式；没有单价只报 token。
9. **时间预算拆分**：把 180 秒拆成可见的分段（例如数据画像 20s / 基线 30s / 候选 4×20s / 预留测试 30s / 报告 20s / 缓冲 20s），超时即切“部分完成”。具体秒数以实测调。
10. **云回包可复现**：保存 prompt hash、response hash、模型配置、seed、temperature；`replay` 只用记录重建决策，不重新调用云模型。
11. **失败语义**：定义重试次数、失败签名、重试窗口和回退规则；同一错误签名两次才云诊断，云回包无效则回到规则路径。

### 18.3 收尾（冻结前）

12. **Streamlit 运行方式**：确定 `session_state + 子进程 + 事件文件轮询`，避免一次 180 秒运行把页面卡死；页面轮询 `.arc/runner-events.jsonl` 展示进度。
13. **前端彩排**：把“创建任务 → 跟踪研究 → 审查结论 → 下载复现包”和“低预算触发 `budget_blocked`”各跑一遍，截图留档。
14. **离线依赖验证**：requirements lock + 离线 wheel 目录，从干净环境执行一次启动命令；Streamlit 坏掉时 CLI 全流程可顶替。
15. **自迭代证据**：证据 A（同题二次运行更省）必须在冻结前输出实测数字；时间允许再跑证据 B（第二数据/任务迁移）。
16. **封存演示快照**：数据哈希、切分、种子、参数、运行日志、复现包版本和 P0 验收清单逐项打勾结果全部放进交付包，评审现场不再改。
