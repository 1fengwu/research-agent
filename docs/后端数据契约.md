# AutoResearch 后端数据契约

**版本**：`autoresearch-outputs-v1`

**目的**：把前端、API 队友、评审回放所消费的后端产物结构固定下来。任何
字段变更必须同步更新本文件与 `autoresearch/tests/test_output_contracts.py`。

## 1. 产物总表

| 文件 | 产生方 | 消费方 | 用途 |
|---|---|---|---|
| `runner-events.jsonl` | A 主循环 | D 页面、C replay、评审 | 研究过程事件流 |
| `summary-<run_id>.json` | A 主循环 | D 页面、C replay | 单次运行结论摘要 |
| `task.json` | A/C 启动 | replay、CLI run | 重建任务的完整配置 |
| `ledgers/<run_id>.json` | A 预算门 | D 页面、C replay、评审 | 候选/云调用/token 账本 |
| `verdicts/<run_id>.json` | C oracle | D 页面、C replay | 每条裁决记录 |
| `pre_gate.json` | C pre_gate | A 启动前判断、评审 | 数据是否值得研究 |
| `metrics.json / metrics.csv` | C evaluate | D 页面、评审 | A/B/C 三臂系统指标 |
| `repro/<run_id>/summary.json` | C replay | D 页面、评审 | 复现对账结果 |
| `report-*.md` | D report | 评审 | 可下载报告 |
| `reproduce-*.zip` | D report | 评审 | 报告、指标、事件、复现包 |

所有文件均使用 UTF-8；时间字段使用 ISO 8601；数值字段若缺失用
`null`，不得伪造 0。

## 2. RunEvent（事件流每一行）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `type` | string | 是 | `research.*` 事件类型 |
| `phase` | string | 是 | 当前阶段，如 `UNSEEN/PLANNING/TESTED` |
| `timestamp` | string | 是 | ISO 8601 时间戳 |
| `run_id` | string | 是 | 每次运行唯一 |
| `decision_reason` | string | 是 | 决策原因 |
| `experiment_id` | string | 是 | 关联实验，无则为空 |
| `tokens` | object | 是 | 云调用 token 统计，无调用为空对象 |
| `remaining` | object | 是 | 预算快照 |
| `extra` | object | 是 | 与该事件相关的数据 |

## 3. summary-<run_id>.json

顶层字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `run_id` | string | 运行编号 |
| `task_id` | string | 任务编号 |
| `phase` | string | `TESTED / FAILED / PARTIAL_COMPLETED` 等 |
| `stop_reason` | string | 停止原因 |
| `tested` | bool | 是否完成独立测试 |
| `locked` | object | 最终锁定记录 |
| `test_verdict` | object | 最终 holdout 裁决 |
| `budget` | object | 预算快照 |
| `ledger` | object | 账本快照（内容同第 5 节） |
| `elapsed_seconds` | number | 墙钟 |
| `event_path` | string | 事件文件路径 |
| `experiments` | array | 实验、TrialResult、verdict |
| `evidence_ids` | array | 证据编号 |
| `stall_rounds` | int | 无进展轮次 |
| `window_conflict` | bool | 是否需要窗口冲突处理 |
| `repeated_error_signature` | bool | 重复错误 |
| `error_signatures` | object | 错误签名计数 |
| `escalation_attempts` | int | 云升级尝试数 |
| `escalation_valid` | int | 有效云回包数 |
| `data_hash` | string | 数据指纹 |
| `split_fingerprint` | string | 切分指纹 |

## 4. Verdict

出现在 `summary.test_verdict`、`experiments[].verdict` 与
`verdicts/<run_id>.json` 中的每条记录：

```json
{
  "verdict": "supported|refuted|inconclusive|blocked|partial_completed",
  "metric": {},
  "checks": [],
  "evidence_ids": [],
  "tokens": 0,
  "seconds": 0.0,
  "artifacts_hash": "sha256:...",
  "test": false
}
```

`verdicts/<run_id>.json` 是记录数组，每条额外包含 `run_id` 与
`experiment_id`。

## 5. ledger

| 字段 | 类型 | 说明 |
|---|---|---|
| `used_candidates` | int | 已用候选数 |
| `used_cloud_calls` | int | 已用云调用数 |
| `used_cloud_tokens` | int | 已用云 token |
| `entries` | array | 明细 |
| `updated_at` | string | 更新时间 |

`entries[]` 的 `kind` 只允许 `candidate` 或 `cloud_call`：

- `candidate`：`kind/ts/note/snapshot`
- `cloud_call`：`kind/ts/estimated_input/actual_input/actual_output/charged/decision_note`

## 6. pre_gate.json

顶层：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 固定 `autoresearch-pre-gate-v1` |
| `task_id / data_hash / split_fingerprint / seed` | string/int | 任务与指纹 |
| `reps` | int | bootstrap 次数 |
| `conclusion` | string | `pass/fail` |
| `passed` | bool | 是否通过 |
| `reasons` | array | 结论原因 |
| `baseline` | object | 基线的 `merged_auc/val1/val2` |
| `candidates` | array | 候选行 |

候选行：

| 字段 | 类型 | 说明 |
|---|---|---|
| `experiment_id` | string | 候选编号 |
| `merged_auc` | number | 合并 AUC |
| `val1 / val2` | object | `auc/valid_days/excluded` |
| `paired_ci` | object | `val1/val2/merged` 三组 CI |
| `passed` | bool | 是否通过 |
| `reasons` | array | 未通过原因 |

## 7. metrics.json / metrics.csv

顶层：`schema_version / task_id / completion_rate / arms`。

每臂一行，字段：

`run_id / arm / completion / phase / test_auc / locked / stop_reason /
candidates / cloud_calls / input_tokens / output_tokens / charged_tokens /
usage_source / cost / wall_seconds`

`usage_source` 只允许 `none / actual / offline_simulated / estimated / unknown`；
没有真实用量时不得填 0 冒充真实。

## 8. replay 输出

顶层：

`schema_version / run_id / status / checks / replay_metric /
recorded_metric / cloud_calls_replayed`

`status` 只允许 `match/mismatch`；`checks[]` 每条为
`name/passed/detail`；`cloud_calls_replayed` 必须是 0。

## 9. 云 API 契约（给 API 队友）

API 队友改 `llm_router.py` 时，后端契约不变：

1. 云调用必须在 `ledger.entries[]` 写一条 `kind="cloud_call"`；
2. usage 缺失时进入 `estimated/unknown`，禁止虚构金额；
3. 事件 `research.escalation` 的 `extra` 至少包含 `trigger/evidence_ids/actions`；
4. 无效回包写 `research.escalation_invalid` 并回规则路径；
5. 不回写 D 页面或报告结构，前端只读事件与上面文件。

## 10. 校验方式

```bash
python -m unittest autoresearch.tests.test_output_contracts -v
python -m unittest discover -s autoresearch/tests -v
```

`autoresearch/outputs.py` 提供每个产物的校验函数；新增字段时允许只扩展
文档与校验器，不破坏旧消费方。
