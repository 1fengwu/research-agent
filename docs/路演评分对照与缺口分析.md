# 路演评分对照与缺口分析

**依据**：用户提供的飞书 wiki《BoHack 2026 黑客松评审规则与奖励设置》中可读取的正文，以及当前 `autoresearch/` 已实现功能。

## 1. 已读到的路演规则

| 规则 | 内容 |
|---|---|
| 路演时长 | 每组 4 分钟，不设置单独答辩环节 |
| 第二轮分值 | 满分 100 分，共 6 个维度 |
| 评委构成 | 企业赛道负责人评分占 50%，其他评委平均分占 50% |
| 第二轮关注点 | 整体完成质量、技术价值与应用潜力 |
| 第一轮形式 | 游园会评审，观看 Demo、听取介绍、查看开发成果、现场交流 |
| 第一轮分值 | 满分 30 分，共 6 个维度；仅用于晋级，不计入第二轮最终成绩 |
| 晋级规则 | 8 个赛道各前 3 名共 24 组，直接晋级；综合补位 6 组，共 30 组进入路演 |
| 现场要求 | 参赛团队应准备必要的项目演示和技术材料，配合评委现场核验 |
| 特别激励 | 针对企业赛道「Built for Better」主题原则，与常规奖项独立，不额外排名 |

> 说明：第二轮“6 个维度”的具体名称和分值在文档内嵌表格中，匿名抓取只能拿到表格 token，无法读取单元格内容。本文先把已知规则和当前能力对完，剩余维度需要你提供表格内容或截图后再逐项补齐。

## 2. 当前系统已覆盖的能力

| 路演环节 | 当前实现 | 覆盖度 |
|---|---|---|
| Demo 演示 | Streamlit 三标签页：创建任务 / 跟踪研究 / 审查结论 | 已覆盖 |
| 4 分钟现场流程 | `mock_events.json` 内置完整运行与低预算运行 | 已覆盖，但缺少一键路演引导 |
| 完整研究闭环 | 基线 → 候选 → 证据修正 → 锁定 → 独立测试 → 报告 | 已覆盖 |
| 预算控制 | `budget_blocked`、剩余 token/时间/实验、PARTIAL_COMPLETED | 已覆盖 |
| 证据驱动修正 | `research.revised`、证据编号、窗口下滑 refuted | 已覆盖 |
| 独立裁判 | C 的 oracle 锁定后唯一打分，防止伪造提升 | 已覆盖 |
| 复现 | `replay.py` 无云复现、复现包 zip、run 命令 | 已覆盖 |
| CLI 降级 | `python -m autoresearch.cli demo/replay/run` | 已覆盖 |
| 数据核验 | 数据哈希、切分指纹、画像、上传 CSV 校验 | 已覆盖 |
| 多运行切换 | 侧边栏按 `run_id` 切换完整运行和低预算运行 | 已覆盖 |

## 3. 当前明显缺口

### 3.1 缺少“游园会评审 / 技术材料”页面

第一轮评委是“走到展位、看 Demo、看项目介绍、查开发成果、现场交流”。当前 Streamlit 是操作台，不是评审材料页。

缺少：

- 项目背景一页纸；
- 技术架构图或模块关系说明；
- 完成成果清单；
- 运行环境、依赖、测试结果；
- 复现包下载入口的静态展示；
- A/B/C/D 四人分工和交接证据。

### 3.2 缺少“路演模式”现场引导

4 分钟很短，当前需要手动切换标签和运行，容易乱。

建议：

- 增加“一键路演”按钮；
- 自动选择完整运行 `R20261114-001`；
- 按 0-30s / 30-90s / 90-150s / 150-240s 给出提示；
- 页面顶部放 4 分钟倒计时；
- 演示结束后一键切到低预算运行。

### 3.3 三臂指标和前置门没有现场演示数据

代码已经支持 `pre_gate.json` 和 `metrics.json`，但仓库没有内置样例，现场可能显示：

```text
未找到 metrics.json，三臂对照暂不可用。
```

这会让“系统自评估”这个评分点展示不出来。

建议：

- 增加 `autoresearch/mock_pre_gate.json`；
- 增加 `autoresearch/mock_metrics.json`；
- 页面在 `.arc` 没有真实文件时自动回退到 mock。

### 3.4 没有“Built for Better”特别激励展示

企业赛道特别激励与项目分数独立，但前提是评委认定项目符合「Built for Better」。

当前界面没有任何地方说明项目如何体现该主题。

建议增加：

- 主题阐释卡片“Built for Better”；
- 项目对主题的具体呼应：可复现、可审计、可降级、诚实报告负结果；
- 在创建任务页或首页加一个固定展示区。

### 3.5 概念表述有风险

现在的系统不是“预测 5 天后推荐股票”，而是：

> 验证 t 日及之前的量价信息，对“未来 5 个交易日收益是否高于同日中位数”是否具有预测力。

路演中不要说是投资建议，否则评委可能按“预测准确性 / 收益高低”评分，而不是按“研究闭环 / 预算 / 验证 / 复现”评分。

## 4. 建议补齐顺序

1. 内置 `mock_pre_gate.json` 和 `mock_metrics.json`，保证三臂和前置门随时可展示；
2. 增加“评审材料”标签页或静态下载页；
3. 增加“路演模式”和 4 分钟流程提示；
4. 增加「Built for Better」主题展示；
5. 提供 6 维度评分表后，再逐条映射到页面。

## 5. 第二轮 6 个评分维度

| 维度 | 分值 | 主要考察内容 | 当前功能支撑 | 现场怎么展示 | 当前缺口 |
|---|---|---|---|---|---|
| 项目完成度 | 20 分 | 功能实现、成果完整性及实际演示效果 | 完整研究闭环、三标签页、CLI、报告、复现包、35 项测试 | 展示完整运行：基线 → 证据修正 → 锁定 → 独立测试 → 下载 | 没有“一键路演”模式，现场容易切错；mock 三臂/前置门数据未内置 |
| 技术难度 | 20 分 | 技术实现复杂度、核心技术突破及解决问题的能力 | 状态机编排、预算门、oracle 唯一裁判、指纹去重、无云复现、三臂评测 | 讲透 4 个机制：预算拦截、窗口下滑 refuted、伪造提升被拒、无云 replay | 页面没有“技术架构/核心技术”展示区，评委看不到技术复杂度 |
| 代码质量 | 10 分 | 代码结构、规范性、文档及可复现性 | 分层模块、契约校验、35 项测试、文档、复现包、CLI | 打开测试输出、复现包内容、README、契约样例 | 没有测试覆盖率和依赖 lock；测试证据没有在页面展示 |
| 商业价值 | 20 分 | 用户需求、应用潜力、商业可行性及实际价值 | 面向量化研究员：信号验证、预算审计、可复现报告 | 讲用户场景：研究员验证量价信号、团队节省 token、评审可追溯 | 页面没有“目标用户/应用场景/商业价值”说明块 |
| 创新性 | 20 分 | 技术、产品、模式及解决思路的创新程度 | oracle 唯一出分、B 不碰裁判、budget_blocked 可见、refuted 可见、无云 replay、每次运行独立 ledger | 展示“伪造实验被拒绝”“证据否定假设”“降级可复现”三个亮点 | 页面没有“创新点”展示区，观众只能从流程中自己找 |
| 现场展示与讲解 | 10 分 | 路演逻辑、表达能力及展示效果 | mock 两条运行、多运行切换、CLI 降级 | 4 分钟按“问题→闭环→预算→复现”讲 | 没有 4 分钟倒计时、步骤提示和一键切运行 |

## 6. 按评分维度的补充建议

### 对“项目完成度”补什么

- 增加“路演模式”：一键进入完整运行、自动隐藏多余按钮、顶部显示 4 分钟倒计时；
- 内置 `mock_pre_gate.json` 和 `mock_metrics.json`，保证前置门和三臂指标随时可展示。

### 对“技术难度”补什么

- 增加“技术架构”区：A/B/C/D 四层、事件流、ledger、oracle、replay 的数据流；
- 演示“同配置只跑一次”“预算不足不调用云”“无云复现不改写结论”。

### 对“代码质量”补什么

- 在页面或 README 展示测试命令和通过数；
- 增加依赖 lock 或 requirements 校验结果；
- 复现包中保留完整的 `run-command.txt`、事件流、账本、数据哈希和切分指纹。

### 对“商业价值”补什么

- 增加固定文案：目标用户是量化研究员；
- 展示解决的实际问题：验证信号是否可复现、预算是否可审计、结论是否可归因；
- 说明可落地场景：研究团队信号筛选、低预算降级、合规审计。

### 对“创新性”补什么

- 页面上固定展示 3 个创新点：裁判隔离、证据驱动修正、无云复现；
- 演示一次“伪造无泄漏但分数变好”被 oracle 拒绝的路径；
- 展示「Built for Better」主题：诚实报告负结果、预算透明、可复现可审计。

### 对“现场展示与讲解”补什么

- 准备 4 分钟讲稿：问题 → 完整闭环 → 预算拦截 → 复现包 → CLI 降级；
- 页面增加“下一步提示”，评委不用猜你讲到哪；
- 现场使用预置 mock 运行，不现场等待真实计算。
